# Читательский клуб — инструмент заметок к цитатам

@DOCS.md

## Что это

Шесть человек читают книги и записывают к цитатам вопросы, комментарии и мысли.
Заметки живут в Google Документе, у каждого участника своя вкладка.
Задача: чтобы ссылка на цитату была коротким номером, а не выписанной цитатой,
и чтобы вставлялась быстро.

Полное описание инструмента и выходных файлов — в `DOCS.md` (импортирован выше).
Здесь только решения, план и грабли.

## Архитектура

**Apps Script не используется.** Обе дороги кончаются буфером обмена, значит в
Google Docs ничего не нужно вставлять программно — человек жмёт Ctrl+V сам.
Ни дополнения, ни манифеста, ни scopes, ни установки у шести человек.
Раньше в плане была боковая панель — от неё отказались, возвращаться не нужно.

Остаётся одна HTML-страница на книгу, собираемая `bookreg.py`:

1. Книга → реестр глава/абзац/предложение (JSON) + читалка (HTML с якорями).
2. Читаешь с экрана: выделил мышкой → всплыла панель → нажал `К`, `?` или `М`.
3. Читаешь с бумаги: набрал начало цитаты в поиске → выбрал → то же выделение,
   та же панель. Поиск — это способ сделать выделение, а не отдельный режим.
   В то же поле можно ввести номер (`1.14.2-4`) или целую ссылку — распознаётся
   и разрешается напрямую.
4. В буфере оказывается готовая строка, в документе — Ctrl+V.

### Что умеет читалка

Выделение мышкой или тапом, три типа заметок, накопитель на несколько цитат,
куски цитаты через «…+», личные метки, поиск по словам и по номеру, оглавление,
три темы, сноски, картинки, таблицы.

### Накопитель и метки

Одна заметка может опираться на несколько цитат: кнопка `+` собирает якоря,
нажатие типа выдаёт их разом. Это оказалось важнее меток — подозрение было,
что метки в отзывах появились как обходной путь именно этой нехватки.

Метки **личные**, список в `localStorage`, не в репозитории. Общий словарь
меток решили пока не заводить.

### Что кладётся в буфер

```
К [1.14.1-4]                     ← номер это гиперссылка на фрагмент
? [1.14.3]
М [1.14.3] «нечего терять»       ← у М добавляется триггер, до 8 слов
```

Тип впереди ссылки намеренно: якоря разной длины (`1.14` и `2.3.9.2-2.3.10.1`),
и при ссылке впереди маркеры встают рваным краем. С типом впереди они
выстраиваются по левому краю и вкладка просматривается глазом сверху вниз.
Висящий пробел на конце — курсор встаёт сразу после вставки.

В буфер пишутся оба представления: `text/html` (Docs сохранит гиперссылку) и
`text/plain` в виде markdown-ссылки.

### Наведение

Смарт-чипы Workspace были единственной причиной трогать Apps Script. Без них
Docs показывает при наведении сам адрес. Планируется класть в адрес первые
слова цитаты (`#2.3.9.2?q=Всеобщее+избирательное`) — это и подсказка при
наведении, и самопочинка ссылки, если нумерация когда-нибудь сдвинется.
**Ещё не сделано.**

## Что дальше

1. **Проверять руками то, чего не видит стенд:** как ложатся цвета в трёх
   темах, поведение на телефоне, вставку в Google Docs.
2. **Хостинг — GitHub Pages, решено.** Публичный репозиторий, `.nojekyll` в
   корне, Settings → Pages → ветка `main`, папка root. Базовый адрес нигде не
   прописан: читалка берёт его из `location.href`. Следствие, которое надо
   помнить: сайт публичный, поэтому книги не из общественного достояния сюда
   класть нельзя — для них понадобится закрытый хостинг.
3. **`?q=` в ссылке** — подсказка при наведении и самопочинка якорей.
4. Возможно, смарт-чипы. Участники готовы поставить дополнение, но это
   отдельная история и не блокирует ничего.

**Стенд.** Читалка прогоняется в jsdom с заглушками для `matchMedia`,
`getClientRects` и `execCommand`. Запускать после **любой** правки читалки:
несколько поломок подряд дошли до пользователя именно потому, что стенда не
было.

```bash
node t_reader.js books/state.html     # общий: выделение, панель, копирование
node t_reader.js books/manifest.html  # то же на второй книге
node seq.js    # сбор кусков, в том числе при протяжке с паузой
node seq2.js   # накопитель вместе с кусками, полоска внизу
node seq3.js   # клик мимо текста, наведение на фишки, выравнивание кнопок
node seq4.js   # что отмечается в тексте в каждом из режимов
node seq5.js   # порядок кусков и цитат, разделение по принадлежности
```

Ожидаемое: во всех — ноль ошибок, во вставляемых строках якоря идут по
порядку книги.

**Требование к скорости.** Сейчас цитата попадает в заметку за ~3 секунды
копипастом. Целевой путь короче: выделил → нажал клавишу → Ctrl+V. Если
привязка станет длиннее нынешнего — формат забросят. Это требование не
размывать.

## Грабли — не наступать заново

- **`\d` в JS внутри Python-строки.** Уехало `\\d` → в JavaScript это «слэш и
  буква d». Регулярка не совпадала никогда. Использовать `r"""..."""` и
  проверять сгенерированный файл, а не исходник.
- **`hashchange`.** Без подписки правка адреса в открытой вкладке ничего не
  делает. Одиночный якорь при этом работает через CSS `:target` и маскирует
  поломку диапазонов.
- **Кодировка HTML.** `lxml` без объявленного charset угадывает cp1252 и молча
  превращает кириллицу в «ÐÐ°Ð½Ð¸Ñ». Декодировать явно: utf-8 → cp1251 →
  koi8-r, отбраковывая по доле латинских Ã/Ð/Ñ. latin-1 не пробовать никогда.
- **Фильтр мусора.** «оглавление» и «содержание» — обычные русские слова,
  фильтр съел живой абзац Маркса. Применять только к блокам < 200 знаков.
- **Текст не только в `<p>`.** В FB2 финальное «ПРОЛЕТАРИИ ВСЕХ СТРАН,
  СОЕДИНЯЙТЕСЬ!» лежит в `<cite><subtitle>`. Внутри cite/epigraph брать
  `p`, `subtitle`, `v`.
- **Позиции сносок.** Считать через сентинелы в тексте, а не заранее: `clean()`
  схлопывает пробелы и сдвигает всё посчитанное.
- **Сноски бывают в заголовках глав и внутри других сносок.**
- **Встроенное оформление нельзя подмешивать в `text`.** Курсив и полужирный
  хранятся отдельными диапазонами (`fmt`), потому что `text` уходит и в
  поисковый индекс, и в буфер обмена при копировании цитаты. У Ленина 447
  фрагментов курсива — это смысл, а не украшение, терять его нельзя.
- **Диапазон оформления пересекает границу предложения.** Обрезать по
  границам, иначе в HTML получаются непарные теги внутри `span.s`.
- **`\s*` в замене съедает пробел.** При переводе кавычек в ёлочки соседние
  цитаты слиплись в `»«`, razdel перестал видеть границу, и три предложения
  исчезли. Пробел в перестановках сохранять явно.
- **Порядок правил с многоточием.** Между цитатами `конец"… "начало` многоточие
  принадлежит концу первой. Закрывающее правило применять первым, иначе
  многоточие уезжает в следующую цитату.
- **Не менять текст книги по умолчанию.** Приведение кавычек к ёлочкам
  сделано ключом `--quotes` и выключено: решили оставлять оригинал. Любое
  преобразование текста должно быть опцией, а не поведением по умолчанию.
- **Исходники побиты распознаванием.** В «Государстве и революции» 22 абзаца
  с несходящимися кавычками, часть — просто потерянный символ («продукт и
  проявление" непримиримости»). Алгоритм тут бессилен; задача — не сделать
  хуже и показать места человеку.
- **`<text-author>` в FB2** — атрибуция под цитатой, 22 штуки у Ленина.
  Обход только по `p`/`subtitle`/`v` терял их молча.
- **Единственный `<h1>` в начале HTML** — название книги, а не глава. Считать
  «начало» после выброса рекламной шапки.
- **`navigator.clipboard.write` требует https или localhost.** На `file://` не
  работает — нужен запасной путь через `execCommand('copy')` с временным
  contenteditable-блоком. Он ломает выделение пользователя, поэтому выделение
  надо сохранить и вернуть.
- **Клавиши в двух раскладках.** `event.key` в русской раскладке даёт `к`, `м`,
  а не `k`, `m`. Принимать оба алфавита плюс цифры 1/2/3.
- **Морфологии в браузере нет.** pymorphy в JS не запустить; обрезка основы до
  5 букв ловит падежи не хуже. Проверено на «пролетариев/пролетарии»,
  «государство/государства», «избирательное/избирательного».
- **Выделение снимается при клике в поле — предотвратить нельзя.** Это
  поведение браузера. Флаги и проверка `document.activeElement` в
  `selectionchange` не помогают: выделение схлопывается раньше, чем переезжает
  фокус. Единственное решение — не зависеть от системного выделения: хранить
  выбор своим состоянием и подсвечивать своим классом.
- **Панель позиционировать по элементам, а не по выделению.** Иначе обработчик
  прокрутки при пустом выделении вызывает `hide()` и убивает выбор.
- **Не выбирать за человека тип заметки.** `Enter` в поле метки вставлял
  «последним типом», а начальным значением стояло `К` — то есть первый раз
  всегда `К`. Убрано: `Enter` только закрывает набор метки.
- **`<datalist>` не даёт удалять записи по одной.** А в личном списке меток за
  полгода копятся опечатки, и убирать их нужно поштучно. Свой выпадающий
  список вышел и удобнее, и одинаковее по браузерам.
- **Замена в строке разметки срывается молча.** Дважды не применилась правка
  панели из-за лишнего пробела в строке поиска; JS искал элемент, не находил и
  тихо ничего не делал. После каждой правки разметки проверять наличие
  элемента в сгенерированном HTML, а не в исходнике.
- **`localStorage` свой у каждого адреса.** Метки и накопитель, заведённые на
  `file://` или `localhost`, на сайте отсутствуют. Выглядит как пропавшая
  функция. Поэтому переключатель такой возможности должен быть виден всегда, даже
  когда скрыто всё, чем он управляет.
- **Инициализацию вызывать после всех объявлений.** `applyHash_()` стоял выше
  `var tagBox`: из-за подъёма `var` переменная была `undefined`, охранная
  проверка `if(tagBox)` не проходила, и поле не пряталось при загрузке. Ошибки
  при этом нет — просто ничего не происходит. Начальное состояние элемента
  дублировать в разметке, чтобы оно не зависело от момента запуска скрипта.
- **Сенсор — отдельная ветка поведения, а не media-query.** Системное меню
  выделения перекрывает панель, протягивание пальцем неточно. Решение: текст
  невыделяемый, выбор тапом, панель прибита к низу. Определять по
  `(hover:none) and (pointer:coarse)`, а не по ширине экрана.
- **Тап надо отличать от прокрутки явно.** Сдвиг пальца > 12 точек, сдвиг
  страницы, касание дольше 500 мс — не тап. Иначе каждая прокрутка выбирает
  предложение.
- **`min-width: 0` для сжимаемых flex-элементов.** Минимальная ширина по
  умолчанию равна ширине содержимого, поэтому длинный placeholder распирал
  верхнюю строку и выдавливал поле метки за край. Перенос на второй ряд был
  лечением симптома.
- **Одна клавиша — одно значение.** `/` значил то «вопрос», то «поиск» в
  зависимости от того, выделено ли что-нибудь. Разведено: `/` — поиск,
  `?` (Shift+/) — вопрос, `#` (Shift+3) — поле метки.
- **Флажок — тоже `<input>`.** Проверка `tagName === 'INPUT'` в охране
  клавиатурных сокращений глушила их, пока фокус стоял на галочке: нажатие не
  проходило, а на ней оставалась рамка фокуса. Отличать поля ввода текста от
  переключателей по `type`.
- **Событие из поля всплывает до `window`.** Обработчик на элементе отработал и
  снял фокус — глобальный обработчик тут же увидел, что фокус свободен, и
  выполнил обратное действие тем же нажатием. Нужен `stopPropagation`, одного
  `preventDefault` мало.
- **Предупреждать надо о том, что случилось, а не о том, что могло.** `verify`
  говорил «текст изменился» и печатал «← ЭТО ОПАСНО» рядом с нулём сдвигов:
  после правки кавычек хеш меняется, а границы предложений нет. Разведено на
  три исхода: не менялся / изменился, но якоря целы / якоря съехали.
- **Догадка не должна переписывать решения человека.** Перестановка многоточия
  применялась ко всем ёлочкам подряд, включая уже расставленные вручную в
  исходнике, — и молча отменяла правки. Кавычки, поставленные скриптом,
  помечаются служебным символом, и перестановка идёт только по ним.
- **Не привязывать вывод к абзацам.** Заголовок главы печатался при встрече
  первого абзаца этой главы — и глава-контейнер с подглавами, у которой своих
  абзацев нет, не выводилась вообще. Той же болезнью болела картинка в конце
  главы. Проверять покрытие: всё, что есть в реестре, должно найтись в HTML.
- **Проверять то, что защищаешь, а не то, что удобно.** `verify` сравнивал хеш
  текста, а защищал якоря. Перенос предисловия в переднюю часть сдвигает все
  номера, не меняя ни слова: хеш совпадал, и проверка говорила «всё цело» при
  полностью сломанных ссылках. Ложное «всё хорошо» опаснее ложной тревоги.
- **Массовый сдвиг — не тысяча поломок, а одна.** Если у всех якорей изменилась
  первая цифра одинаково, это одно событие, и сообщать надо о нём, а не
  печатать список на тысячу строк.
- **Тему ставить до отрисовки.** Скрипт выбора темы должен стоять в шапке
  перед `<style>`, иначе страница мигает белым при каждой загрузке.
- **Цвета — только через переменные.** До тёмной темы в читалке было 43
  жёстко заданных цвета; тема без их сведения дала бы дырявую картинку.
- **Полям ввода задавать и фон, и цвет текста.** Браузер по умолчанию рисует
  поле белым с чёрным текстом. В тёмной теме одно поле осталось белым, а
  другое получило тёмный фон с чёрным текстом — печатаешь вслепую.
- **`str.replace` без счётчика бьёт по всем вхождениям.** Палитра читалки
  попала заодно в стили списка книг: строка `html[data-theme="dark"]{`
  встречалась в двух разных блоках CSS.
- **Системное выделение задавать явно.** По умолчанию браузер рисует яркую
  синь с белым текстом; поверх собственной подсветки предложения это
  нечитаемо, особенно в тёмной теме. Нужен `::selection` на каждую палитру.
- **`mix-blend-mode: screen` не годится для тёмного фона.** Он высветляет и
  текст, и фон, контраст падает. В тёмной теме — обычное наложение с низкой
  прозрачностью.
- **Значки в кнопке-переключателе разной ширины.** ◑ ◕ ● двигали соседнюю
  строку поиска. Фиксированной ширины кнопки не хватило — сами глифы разного
  размера в любом шрифте. Значок нарисован кружком через CSS.
- **Не полагаться на сочетания клавиш для основного действия.** Ctrl+протяжку
  Chrome на маке перехватывает под своё. Основной путь должен быть кнопкой,
  клавиша — ускорением.
- **Собственный `removeAllRanges` выглядит как клик по пустому месту.**
  Обработчик, снимающий выбор при щелчке мимо текста, стирал только что
  собранные куски через 10 мс. Нужен флаг «это сделали мы».
- **Панели должны быть `user-select:none`.** Иначе протяжка вверх захватывает
  текст кнопок и всё, что ниже; при огромном выделении накладка плодила тысячи
  блоков и вешала страницу. Число прямоугольников ограничено.
- **Множественное выделение есть только в Firefox.** `addRange` сверх первого
  диапазона в Chrome и Safari игнорируется. Список кусков ведём сами, системное
  выделение снимаем и рисуем свои накладки.
- **Смещения в символах вместо нумерации слов.** Чтобы подсветить куски по
  ссылке, достаточно `?f=2-35,68-88` — нумеровать слова и раздувать якоря не
  нужно. Считать смещения по текстовым узлам, пропуская маркеры сносок: они
  есть в `textContent`, но не в тексте книги.
- **Копировать через событие `copy`, а не через contenteditable.** Браузер
  сериализует выделение в contenteditable вместе с вычисленными стилями —
  в документ приезжал цвет темы. `clipboardData.setData` кладёт ровно свои
  байты и работает без разрешений и без https.
- **Молча не сообщать об успехе.** Если копирование не удалось, а сообщение
  говорит «скопировано», человек нажмёт Ctrl+V и вставит то, что лежало в
  буфере раньше, не поняв, что произошло.
- **Проверять в настоящем DOM.** jsdom с заглушками для `matchMedia`,
  `getClientRects` и `execCommand` прогоняет весь сценарий: выделение, панель,
  куски, накопитель, подсветку по ссылке. Три подряд поломки ушли бы, будь
  стенд заведён раньше.
- **`show()` при протяжке отрабатывает не один раз.** Если тянуть с паузой,
  отложенный вызов успевает сработать посреди жеста, и всё, что хранилось «до
  следующего выделения», затирается половинкой текущего. Состояние, которое
  должно пережить новое выделение, держать в отдельном списке, а не выводить
  из предыдущего значения.
- **Защитный флаг гасить по времени, а не по следующему событию.**
  `justJoined` ждал следующего `pointerup`, а при клике по панели тот не
  приходил — и клик по пустому месту переставал снимать выбор.
- **На сенсоре не показывать то, что там не работает.** Кнопка «…+» скрыта:
  куски требуют протяжки, а она отдана выбору предложений. Неработающая
  кнопка хуже отсутствующей.
- **Накладка при наведении рисуется поверх текста.** Непрозрачный цвет её
  просто закрывает — нужен свой полупрозрачный тон на каждую тему, отдельно
  от цвета подсветки якоря.
- **Прокрутка — по нажатию, не по наведению.** Автоматический скачок при
  проведении мышью над списком дезориентирует.
- **Полосу прокрутки внутри тёмной панели надо оформлять.** Системная белая
  перекрывает текст под панелью на пару секунд.
- **Отмечать ровно ту единицу, с которой работают.** Накопитель работает
  предложениями — там подчёркивается предложение. Куски работают словами —
  там отмечаются куски, а предложения не трогаются вовсе. Промежуточный
  вариант «подчеркнуть предложения, где есть куски» тоже показывает не то,
  что выбрано.
- **Полоска — для закреплённого, не для живого выделения.** Иначе она
  открывается на каждое движение мышью по тексту.
- **Охват цитаты считать по её кускам, а не по текущему выделению.**
  Расширять `cur` до кусков нельзя — при куске в одном месте и выделении в
  другом это склеивало полкниги в один диапазон. Правильно: у цитаты из
  кусков свой охват (`spanOf`), а `+` откладывает только текущее выделение.
- **Накладки стоят в координатах документа и не едут за текстом.** Догрузилась
  картинка, подменился шрифт, повернули экран — текст уехал вниз, накладки
  остались выше. Лечится двумя вещами сразу: `width`/`height` у картинок
  (читаются из их заголовков) и перерисовка на `resize`, `load`, загрузку
  картинок и `document.fonts.ready`.
- **Различать «указать» и «выбрать».** При `+` выделение — способ показать,
  какую цитату отложить, а не выбор слов: смещения текущей протяжки в
  накопитель не идут, иначе ссылка ведёт на случайный обрывок вместо
  предложения. Слова отмечаются только через «…+».
- **Условия видимости кнопок и клавиш должны совпадать.** Кнопки внизу
  работали при собранных кусках, а клавиши 1/2/3 нет: у них в условии не было
  `kept`. Если действие доступно кнопкой — оно должно быть доступно клавишей.
- **Не выводить состояние из «текущего выделения», если его может не быть.**
  Текст цитаты брался от `cur`; после закрепления последнего куска выделения
  нет, и цитата пропадала. Брать от самих кусков.
- **Одно действие — одно место.** Пока идёт сборка, К/?/М показываются только
  на постоянной нижней полоске; всплывающая панель исчезает при клике мимо и
  владеть завершающим действием не должна.
- **Порядок — по положению в тексте.** И куски внутри цитаты, и цитаты между
  собой: заметку читают сверху вниз.
- **Отложенное в накопитель отмечать в тексте постоянно.** Иначе собранное
  видно только в полоске, а в тексте не найти.
- **Общий вывод.** Каждая из этих ошибок ломала результат молча. Любую правку
  разбора проверять `check` + `verify`, а не глазами по итоговому HTML.

## Формат заметок в Google Документе

```
### 1.14 · Пролетариям нечего терять

К [1.14.1-4] Замечание к тезису автора.
? [1.14.3] Вопрос к обсуждению.

#### Наследование инструмента
М [1.14.3] «нечего терять» Текст мысли.
```

- `К` смотрит внутрь текста (что автор сказал, точно ли это).
- `М` смотрит наружу (что у меня из-за этого сдвинулось). Мысль цепляется за
  слово или оборот, часто не за главный тезис абзаца, — отсюда триггер.
- `?` — вопрос к обсуждению. Перед встречей выносится в блок «К обсуждению»
  вверху вкладки периода, ссылкой на запись.

Вкладки: `Как мы пишем` / книга → период (`П1 · гл. 1–2`) → участник (`##`) /
`Мысли` → участник. Точные даты в файле не пишутся, вместо них номер периода.

bookreg.py           разбор книг и сборка читалки
docs2html.py         сборка html из .md
t_reader.js seq*.js  стенды
books/
  <книга>.fb2        исходники
  <id>.json          реестр
  <id>.lock.json     замороженная нумерация — держать в git
  <id>.html          читалка
  <id>.txt           для проверки глазами
  <id>_img/          картинки из книги
index.html reader.html docs.html   собираются, в git не правятся руками
.nojekyll

копиях репозитория, это мусор.
