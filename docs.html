bookreg — документация

Это руководство для того, кто заводит книги и держит сайт. Если нужно просто завести очередную книгу — весь порядок в разделе 2, остальное справочное. Участникам, которые просто читают и делают заметки, нужно другое — как делать заметки.

Инструмент читательского клуба. Разбирает книгу на главы, абзацы и предложения, присваивает каждому устойчивый номер и собирает читалку, в которой выделение мышкой превращается в готовую строку заметки со ссылкой на фрагмент.

1. Установка

pip install lxml razdel pymorphy3 pymorphy3-dicts-ru
пакет зачем
lxml разбор XML и HTML
razdel деление на предложения по-русски: держит «т. е.», «и т. д.», инициалы, «1848 г.»
pymorphy3 начальные формы слов для поиска из терминала и для панели

Скрипт — один файл, bookreg.py. Ничего больше устанавливать не нужно.

2. Как завести новую книгу

Порядок целиком. Занимает около получаса, из них двадцать минут — глазами. Автоматизировать проверку нельзя: цена ошибки — молча сломанные ссылки у всех участников.

1. Найти файл. FB2 или EPUB предпочтительно, HTML запасным вариантом (раздел 8). Положить в books/, рядом с реестрами: иначе не заработает rebuild.

2. Собрать.

python3 bookreg.py build "books/Капитал.fb2" --id kapital -o books

--id — короткое латинское имя: от него зависят имена файлов и адрес читалки. Менять его потом нельзя, ссылки протухнут.

3. Посмотреть дерево глав в выводе команды. Совпадает ли с оглавлением книги, на месте ли подглавы, не разъехалась ли нумерация. Отдельно — не стала ли главой передняя часть: если «Глава I» вышла под номером 2, нужен --front (раздел 4). Это главная проверка: пропущенный заголовок сдвигает все абзацы после него.

Не совпало — смотреть, как размечены заголовки в исходнике. У FB2 главы задаются вложенностью <section>, у HTML — уровнями <h2>/<h3>; чаще всего дело в том, что заголовок оформлен обычным абзацем. Поправить исходник и пересобрать.

4. Разобрать предупреждения (раздел 7). Ошибки чинить обязательно, предупреждения посмотреть глазами: часть из них — норма для конкретной книги.

5. Пролистать books/kapital.txt по диагонали. Плоский список «номер → предложение»: видно слипшиеся абзацы, оборванные фразы, мусор.

6. Закрепить нумерацию.

python3 bookreg.py freeze books/kapital.json

Откажется работать, пока есть ошибки. После этого номера меняться не должны.

7. Пересобрать сайт.

python3 bookreg.py rebuild books

Обновит index.html: книга появится в списке с отметкой «номера закреплены».

8. Выложить.

git add -A && git commit -m "Капитал" && git push

9. Сказать группе, что книгу можно брать. Отметка в списке — тот же сигнал, участникам объяснено, что до неё заметки делать рано.

Когда меняли читалку

Разбор не трогали — значит нумерация обязана остаться прежней:

python3 bookreg.py rebuild books

Для каждой книги напечатает «нумерация та же» и прогонит verify по закреплённым. Если увидели «СДВИГ» — задели разбор, не заметив, дальше по следующему пункту.

Когда меняли разбор

python3 bookreg.py rebuild books
python3 bookreg.py verify books/kapital.json     # ОБЯЗАТЕЛЬНО

verify покажет, какие якоря съехали и куда уехал каждый текст. Дальше по обстановке:

  • на книгу ещё не ссылались — удалить .lock.json и закрепить заново;
  • ссылок мало — править вручную по карте verify --map, начиная с конца, то есть с бо́льших номеров: иначе замены наложатся друг на друга;
  • ссылок много — не чинить. Оставить старую нумерацию и жить с неточностью: правильные номера не стоят того, чтобы у шестерых человек ссылки указывали в никуда.

Отдельная книга с --id test, которую никогда не закрепляют, избавляет от половины таких случаев: правки разбора проверяются на ней.

Когда меняли документацию

python3 docs2html.py READER.md DOCS.md -o .

Правка .md сама на сайт не доходит.

3. Команды

build — собрать реестр из книги

python3 bookreg.py build ФАЙЛ [--id ИМЯ] [-o ПАПКА] [--no-lemma]
ключ по умолчанию смысл
--id имя файла в нижнем регистре короткое имя книги: определяет имена выходных файлов
-o, --outdir . куда складывать результат
--no-lemma выключено пропустить лемматизацию: сборка заметно быстрее, поиск хуже держит падежи
--front пусто регвыражение для заголовков передней части (см. ниже)
--quotes выключено привести кавычки к ёлочкам и завести многоточие внутрь цитаты (см. ниже)

Форматы: .fb2, .epub, .html, .htm, .xhtml, .txt.

Печатает сводку, дерево глав и отчёт check. Возвращает код 1, если есть ошибки.

Исходник книги стоит класть в ту же папку, что и реестры, — тогда заработает rebuild.

check — проверить качество разбора

python3 bookreg.py check books/kapital.json

Тот же отчёт, что печатает build, но по уже собранному реестру. Код возврата 1 при наличии ошибок — годится для скриптов.

freeze — заморозить нумерацию

python3 bookreg.py freeze books/kapital.json

.lock.json — снимок нумерации на момент заморозки. Инструмент не видит ни сайта, ни заметок в документе: единственный способ сообщить ему, что новое состояние теперь правильное, — перезаморозить. Пока снимок старый, verify будет докладывать о расхождении при каждом запуске, даже если вы давно всё поправили руками.

Пишет kapital.lock.json: контрольную сумму текста и снимок всех якорей. Откажется работать, пока в отчёте есть ошибки.

Делается один раз, перед раздачей файла участникам.

На странице со списком книг состояние видно: «номера закреплены» против «номера ещё могут измениться». Участникам объяснено, что до закрепления заметки делать рано, — см. руководство для них. Так что freeze это ещё и сигнал группе, что книгу можно брать.

verify — что съехало после правки

python3 bookreg.py verify books/kapital.json
python3 bookreg.py verify books/kapital.json --map перенос.tsv

--map выгружает полную карту «старый якорь → новый» — в консоль печатаются только первые 15 строк, а править заметки нужно по всем. Столбцы: старый номер, новый, начало текста. Строка ПОТЕРЯНО означает, что текст предложения изменился и сопоставить автоматически нельзя — такие места смотреть глазами по третьему столбцу.

Что делать с результатом — в разделе 2, «Когда меняли разбор». Сравнивает якоря, а не текст. Это важно: перенос предисловия в переднюю часть (--front) сдвигает все номера, не меняя ни одного слова — проверка по тексту сказала бы «всё цело», когда сломаны все ссылки до единой.

Четыре возможных ответа:

Ничего не изменилось — всё в порядке, делать нечего.

Вся нумерация сдвинута — первая цифра якоря изменилась у всех сразу. Так бывает от --front, от добавленного или убранного предисловия. Сообщение короткое, список не печатается: он был бы на тысячу строк, а полезного в нём одна.

Текст изменился, но все якоря на месте — правили опечатки, кавычки или оформление, границы предложений не двинулись. Ссылки в заметках целы, нужна только перезаморозка.

Якоря съехали — вот это опасно:

! текст изменился с момента заморозки

  исчезли якоря:      60
  появились новые:    59
  номер стал другим:  112   ← ЭТО ОПАСНО

  Эти ссылки в заметках теперь указывают не туда:
    1.2.1        было «свободный и раб патриций и плебей…»
                 стало → теперь 1.1.1

Показывает, куда уехал каждый текст, — по этому списку заметки чинятся заменой. Код возврата 1, если есть сдвиги.

rebuild — пересобрать все книги папки

python3 bookreg.py rebuild books

Проходит по всем реестрам папки, берёт исходник и id из самого реестра (book.source_file, book.id), пересобирает .json, .html, .txt. Для каждой книги сообщает, совпала ли нумерация, и в конце прогоняет verify по всем замороженным.

✓ manifest     абз.  218  предл.   454  нумерация та же
✓ state        абз.  467  предл.  1201  нумерация та же

Нужен после правки читалки: CSS и JS живут внутри bookreg.py и впечатываются в каждый HTML, поэтому улучшение доходит до старых книг только пересборкой. Разбор при этом не менялся — значит нумерация обязана остаться прежней, и rebuild это подтверждает одной командой.

Он же обновляет index.html, поэтому после freeze его надо прогнать, чтобы в списке сменилась отметка.

Требует, чтобы исходники лежали рядом с реестрами.

search — поиск цитаты из терминала

python3 bookreg.py search books/kapital.json "нечего терять" -n 5

Тот же алгоритм, что в читалке (но с настоящей лемматизацией вместо приближения). Годится, чтобы проверить, найдётся ли конкретная цитата.

4. Нумерация

глава        путь-строка: "0", "1", "3.2"
абзац        <глава>.<n>        1.14
предложение  <глава>.<n>.<k>    1.14.3

Глава — путь, а не число. Если у главы есть подглавы, они получают 3.1, 3.2, 3.3. Соответствие с нумерацией самой книги обязательно: номер должен работать в другом издании и произноситься вслух на встрече.

Глава «0» — текст до первого заголовка: преамбула, эпиграф, посвящение.

Якоря

якорь что подсветит
#1.14 абзац целиком
#1.14.2 одно предложение
#1.14.2-4 предложения 2–4 того же абзаца
#4.11.3-4.12.1 отрезок через границу абзаца или главы

Правило: если после дефиса нет точек — это номер предложения в том же абзаце; если есть — полный якорь, и отрезок пойдёт через сколько угодно абзацев.

Устойчивость: если конца диапазона не существует, подсветится до конца абзаца; концы можно указать в обратном порядке.

Передняя часть книги

Глава «0» — это текст до первого заголовка. Если предисловие озаглавлено, оно становится обычной главой, и тогда «Глава I» оказывается второй, «Глава II» третьей и так далее — нумерация расходится с книгой.

Так устроены разные файлы по-разному, и жёстко зашить правило нельзя: у «Манифеста» вступление вообще без заголовка, у «Государства и революции» названо «Предисловие».

Поэтому ключ на книгу:

python3 bookreg.py build книга.fb2 --front 'Предисловие|Введение' …

Заголовки верхнего уровня, совпавшие с выражением, номера главы не получают: их текст уходит в главу «0». Сам заголовок остаётся видимым — выводится как заголовок уровня главы, только без нижней черты, и попадает в оглавление слева. Работает только до первой настоящей главы, так что «Предисловие 1891-го года» внутри четвёртой главы не заденет.

Несколько предисловий подряд — все уйдут в главу «0», нумерация внутри неё сквозная.

Послесловия и приложения в конце этим ключом не затрагиваются: они идут после последней главы, и обычный номер им не мешает.

Режим запоминается в реестре (book.front), rebuild его соблюдает.

Что видно в читалке. Заголовок передней части стоит наравне с главами и есть в оглавлении, так что мотать вверх за предисловием не нужно. Жирные строки внутри него — «ПРЕДИСЛОВИЕ К ПЕРВОМУ ИЗДАНИЮ» и подобные — распознаются отдельно и уходят в оглавление подпунктами.

Проверка front предупредит, если первая глава похожа на предисловие, а ключ не задан. Не срабатывает, если ключ уже стоит или если вступление в книге без заголовка.

Менять после заморозки нельзя — сдвинутся все якоря до единого: первая цифра есть у каждого.

Приведение кавычек — по желанию

По умолчанию текст книги не трогается. Ключ --quotes включает замену прямых кавычек на ёлочки и заводит многоточие внутрь цитаты:

"текст"          →  «текст»
…"текст"…        →  «…текст…»
"внешняя "внутренняя" "  →  «внешняя „внутренняя“ »

В FB2 кавычка одна на оба случая, поэтому открывающая опознаётся по соседу слева: пробел, скобка, тире или многоточие означают начало цитаты.

Порядок правил с многоточием важен. Между двумя цитатами — конец"… "начало — многоточие относится к концу первой: пропуск сделан в ней. Результат: конец…» «начало.

Перестановка применяется только к кавычкам, поставленным догадкой. Если в исходнике уже стоит …«забыл» — это решение автора или редактора, и скрипт его не трогает. Значит ручная правка в исходнике всегда сильнее догадки: поставили ёлочку сами — она останется как есть, вместе с положением многоточия.

Замена перестановочная, длина текста не меняется, поэтому смещения сносок и оформления остаются в силе. Деление на предложения проверено — совпадает до якоря.

Где это может ошибиться. Определение открывающей кавычки — эвристика. Кроме того, исходники бывают побиты распознаванием: в «Государстве и революции» 22 абзаца из 489, где кавычки не сходятся, и часть из них — просто потерянная в файле кавычка, а не цитата через абзац. Такие места помечает проверка quotes; вложенные лапки в них не ставятся, чтобы не выглядело ошибкой заметнее, чем слегка не туда повёрнутая ёлочка.

Это и есть способ исправлять промахи догадки: нашли в читалке неверную кавычку — поставили в исходнике нужную ёлочку вручную, и при следующей сборке останется она.

Поэтому по умолчанию выключено. У Ленина ситуаций слишком много и они слишком разные, чтобы одно правило било в цель везде; там, где источник побит, оно ещё и уверенно ставит неверный символ. Прямые кавычки при этом ничему не мешают: поиск их всё равно отбрасывает при нормализации, а при копировании в документ они выглядят ровно так же, как в книге.

Имеет смысл включать, когда исходник заведомо чистый и набран прямыми кавычками единообразно.

Режим запоминается в реестре (book.quotes), и rebuild пересобирает книгу так же, как она была собрана изначально: включать ключ повторно не нужно и случайно поменять режим при пересборке нельзя.

Заморозка

Номера замораживаются до того, как кто-то начал читать, и дальше не меняются. Один пропущенный заголовок сдвигает все абзацы после него, и ссылки во всех заметках всех участников указывают не туда — молча, без ошибки.

text_sha256 в реестре — контрольная сумма текста. На ней построены freeze, verify и отчёт rebuild.

5. Читалка

Читалка описана отдельно, в руководстве для участников: reader.html (исходник READER.md). Там панель, накопитель, метки, клавиши, поиск и поведение на телефоне.

Здесь — только то, что нужно знать при сборке.

Читалка целиком собирается bookreg.py. CSS и JS лежат константами в скрипте и впечатываются в каждый HTML, поэтому улучшение доходит до старых книг только через rebuild.

Базовый адрес нигде не прописан — берётся из location.href. Где выложили, оттуда и работает, локально тоже.

Заголовки глав выводятся по всей цепочке предков, а не только для главы, которой принадлежит абзац: у главы-контейнера с подглавами своих абзацев нет. Верхний уровень — <h2>, вложенные — <h3>, подзаголовки внутри главы (а), b)) — <h4>.

Темы. Три: light, sepia, dark, кнопка перебирает их по кругу. Каждая задаёт и цвет системного выделения (::selection): по умолчанию браузер рисует его яркой синью с белым текстом, и поверх подсветки выбранного предложения это нечитаемо. Все цвета сведены в переменные CSS, палитры переопределяют их через html[data-theme="…"]. Выбор хранится в localStorage под ключом br.theme — общий для книг, списка и документации. Начальное значение выставляется отдельным скриптом в шапке, до подключения стилей: иначе тёмная страница мигает белым при каждой загрузке. Без сохранённого выбора берётся prefers-color-scheme.

Две панели. Всплывающая над выделением — для одиночной заметки. Как только что-то отложено или закреплено, вставка переходит на нижнюю полоску, а наверху остаются только + и …+: полоска постоянная, всплывающая исчезает при первом клике мимо текста.

Куски цитаты. Основной путь — кнопка «…+» на панели или клавиша «минус»: выделили кусок, закрепили, выделили следующий. Ctrl+протяжка делает то же без кнопки, но Chrome на маке перехватывает это сочетание, поэтому полагаться на неё нельзя.

Ссылка подсвечивает то, что заметка цитирует. У К и ? цитаты нет — ?f= не добавляется, протяжка означает «вот это место»: иначе, чтобы сослаться на предложение целиком, пришлось бы тянуть выделение до последней точки. У М цитата есть, и смещения ставятся всегда. Куски, отмеченные через «…+», дают смещения при любом типе — их для того и отмечали.

Если кусок покрывает весь охват, offsetsFor возвращает пусто сам, так что выделение предложения целиком подсветки не порождает.

Накопитель хранит не голые номера, а пары «якорь + куски», поэтому нажатие + не теряет отмеченные слова. Старый формат (просто строки) читается тоже. Подсветка ?f= добавляется при любом типе заметки, а сама цитата попадает в документ только у М.

На сенсорных экранах куски недоступны: протяжка там занята выбором предложений.

Куски хранятся живыми Range. Множественное выделение поддерживает только Firefox, поэтому список ведётся самостоятельно, а подсветка рисуется накладками.

В ссылку они уходят символьными смещениями внутри якоря: #1.3.1?f=2-35,68-88. Нумеровать слова не понадобилось, и адрес остаётся коротким — три куска дают 27 знаков. При открытии ссылки смещения превращаются обратно в диапазоны и подсвечиваются. Если текст книги изменится, подсветка сместится — но это видно глазом, в отличие от съехавшего якоря.

Оглавление собирается из заголовков глав, подзаголовков внутри них и жирных строк-заголовков вроде «ПРЕДИСЛОВИЕ К ПЕРВОМУ ИЗДАНИЮ». Первым пунктом — название книги, возврат в начало: он нужен всегда, но особенно там, где вступление без заголовка и своего пункта не имеет — так устроен «Манифест». От 1180 точек стоит слева постоянно, уже — открывается кнопкой в верхней строке. Текущая глава подсвечивается при прокрутке.

Ссылка «← Книги» ведёт на ../index.html и рассчитана на раскладку из раздела 9: читалки в books/, индекс уровнем выше.

navigator.clipboard.write требует https или localhost. При открытии файла прямо с диска включается запасной путь через execCommand('copy'). Проверять копирование лучше на выложенной версии.

Накопитель, метки и положение переключателя лежат в localStorage, а он свой у каждого адреса. Заведённое локально на сайте отсутствует, и наоборот. Это не потеря данных, но выглядит как пропавшая настройка — на новом адресе всё начинается с чистого листа.

6. Выходные файлы

<id>.json — реестр

Основной артефакт: на нём строится читалка и всё остальное.

{
  "book": {
    "id": "state",
    "title": "Государство и революция",
    "authors": ["Владимир Ильич Ленин"],
    "source_file": "Государство и революция.fb2",
    "source_format": "fb2",
    "text_sha256": "eb8e70e5740fc90f…"      // контрольная сумма текста
  },
  "chapters": [
    { "id": "2.1", "title": "1. Государство — продукт…",
      "level": 2,
      "refs": [] }                          // сноски на самом заголовке
  ],
  "paragraphs": [
    { "id": "2.1.4", "chapter": "2.1", "n": 4,
      "text": "…",
      "sentences": ["2.1.4.1", "2.1.4.2"],
      "cite": true,                         // абзац из блочной цитаты
      "author": false,                      // атрибуция под цитатой
      "fmt": [ { "pos": 31, "len": 12, "t": "e" } ] }
  ],
  "sentences": [
    { "id": "2.1.4.1", "para": "2.1.4", "chapter": "2.1", "n": 1,
      "text": "…",                          // как в книге, чистый
      "norm": "…",                          // для поиска
      "lemma": "…",                         // начальные формы слов
      "start": 0, "stop": 87,               // смещения внутри абзаца
      "notes": [ { "pos": 24, "note": "n_5" } ],
      "fmt":   [ { "pos": 31, "len": 12, "t": "e" } ] }
  ],
  "marks": [ { "chapter": "3.1", "after": 7, "text": "а) Феодальный социализм" } ],
  "images": [ { "chapter": "2", "after": 87, "href": "coverr.jpg" } ],
  "tables": [ { "chapter": "1", "after": 12, "rows": [ [ ["th","Год"] ] ] } ],
  "notes": {
    "n_5": { "num": "5", "text": "…",
             "refs": [ { "pos": 132, "note": "n_35" } ] }
  }
}

Про поля, которые легко понять неверно:

  • text чистый. Маркеры сносок [4] из него вырезаны — иначе они попадали бы в цитату и ломали поиск. Позиция запомнена в notes.
  • norm — нижний регистр, ё→е, без кавычек и пунктуации; тире между словами выброшено, дефис внутри слова сохранён.
  • lemma — то же, но каждое слово в начальной форме. По нему идёт поиск команды search. Поля нет, если собирали с --no-lemma.
  • cite: true — абзац пришёл из блочной цитаты.
  • author: true — атрибуция под цитатой (в FB2 это <text-author>): «(стр. 177—178 шестого немецкого издания)». В читалке — курсивом справа.
  • fmt — встроенное оформление: pos и len в символах, t — тип. Есть и у абзаца (координаты внутри абзаца), и у предложения (внутри предложения). Диапазон, начавшийся в одном предложении и кончившийся в другом, обрезается по границам, поэтому у каждого предложения оформление замкнуто само в себе.
t что это тег в читалке откуда
e курсив <em> emphasis, <i>, <em>
s полужирный <strong> strong, <b>
k зачёркнутый <s> strikethrough, <del>
b нижний индекс <sub> sub
p верхний индекс <sup> sup
c моноширинный <code> code
y прочее <span> style

text при этом остаётся чистым текстом — оформление в него не подмешивается. Иначе оно попадало бы в цитату при копировании и в поисковый индекс. - images — иллюстрации: after — номер абзаца, после которого стоит картинка. Своего номера не имеют, файлы лежат в <id>_img/. - tables — таблицы, привязка та же. rows — строки, в каждой пары [тег, текст], где тег td или th. Номера тоже не получают. - marks — подзаголовки внутри главы (а), b), с)). Своего уровня нумерации не получают, показываются в читалке. after — номер абзаца, после которого стоит подзаголовок. - notes[*].refs — сноски внутри сносок. Бывают: у Энгельса примечание 1888 года ссылается на семь дальнейших.

<id>.html — читалка

Раздаётся участникам. Всё описано в разделе 5.

index.html — список книг

Собирается командой rebuild в папке над books/. Точка входа для участников: карточки книг со счётчиками и отметкой, заморожена ли нумерация.

<id>_img/ — картинки

Иллюстрации из книги, выложенные отдельными файлами. Папка создаётся только если в книге есть картинки.

В разметку проставляются width и height, прочитанные из заголовка самой картинки: без них браузер не знает, сколько места занять, при догрузке текст сдвигается вниз, а накладки выделений остаются висеть выше него.

Не встраиваются в HTML: у «Манифеста» их 111 КБ, в base64 это 152 КБ поверх страницы, а на книге с полусотней иллюстраций читалка стала бы неподъёмной. Отдельные файлы к тому же кешируются браузером по одному и нормально ложатся в git.

Картинка не получает своего номера. Она привязана к месту («после абзаца 2.87»), но абзацем не считается — иначе добавление иллюстраций сдвинуло бы нумерацию всех абзацев после неё.

Экслибрисы и логотипы электронных библиотек отсеиваются по имени файла (exlibris, fbw, royallib, logo, banner) — тот же мусор, что и рекламный текст.

Картинка внутри абзаца (не отдельным блоком) пока пропускается.

<id>.txt — плоский список

якорь<TAB>текст, по строке на предложение. Для просмотра глазами перед заморозкой. Больше нигде не используется.

<id>.lock.json — замороженная нумерация

Контрольная сумма текста и снимок якорей. Держать в git — это единственная защита от незаметного сдвига нумерации.

7. Проверки check

Ошибки — чинить обязательно

код что значит
empty абзацев не найдено вообще: формат не тот или разметка непонятна
junk реклама электронной библиотеки попала в текст
notemark маркеры сносок [4] остались в тексте — попадут в цитату и сломают поиск
encoding битая кодировка или неразобранные HTML-сущности
note_dangling ссылка на несуществующую сноску

Предупреждения — посмотреть глазами

код что значит обычная причина
headings много коротких абзацев без точки заголовки не опознались как главы — проверять первым делом
nochapters больше 30% текста вне глав заголовки не распознались вовсе
lowstart предложение начинается со строчной абзац продолжает предыдущий после блочной цитаты
noend длинное предложение без знака в конце фраза автора продолжается блочной цитатой
toolong предложение вдвое длиннее 95-го процентиля пропущен разрыв, обычно из-за нестандартной пунктуации
hyphen «слово- вое» неснятый перенос, обычно из PDF
dup одинаковые предложения автор повторяется либо кусок задвоился при разборе
emptychap глава без абзацев нормально для главы-контейнера с подглавами
note_orphan сноска, на которую никто не ссылается в читалке она не появится
front первая глава похожа на предисловие, а --front не задан нумерация глав сдвинута на единицу относительно книги
quotes кавычки не сходятся в абзаце цитата тянется через абзацы либо кавычка потеряна при распознавании исходника

Справочно

код что значит
ambiguous у разных предложений одинаковые первые 5 слов: в поиске придётся выбирать из нескольких. Не ошибка

Как читать noend и lowstart

Пример из «Государства и революции»:

! [noend] Длинное предложение без знака в конце: 6
      2.3.9.2

Смотрим 2.3.9.2:

Всеобщее избирательное право, говорит он, явно учитывая долгий опыт немецкой социал-демократии, есть

Дальше в книге идёт блочная цитата. Ленин вплетает чужие слова в собственную фразу грамматически. Разбор верен, чинить нечего. lowstart — обратная сторона: абзац, подхватывающий прерванную фразу.

Но следствие знать надо. Такая фраза разорвана между абзацами, поэтому сослаться на неё целиком можно только диапазоном (2.3.9.2-2.3.10.1), а поиск по цитате, пересекающей границу абзаца, её не найдёт — он работает в пределах предложения.

Правило: единицы таких предупреждений — почти наверняка блочные цитаты, всё в порядке. Десятки — разбор разваливает обычный текст, надо смотреть.

8. Форматы книг

формат пригодность
FB2 лучший. Структура глав задана вложенностью <section>, сноски отдельным <body name="notes">, маркеры сносок помечены явно
EPUB хорошо. Порядок чтения берётся из spine
HTML запасной. Уровни <h2>/<h3> — типографское решение автора файла, опираться нельзя. Обязателен просмотр списка глав
TXT грубо. Абзацы по пустой строке, заголовки угадываются по длине
PDF не поддерживается. Конвертировать заранее, например Calibre
скан сначала OCR; качество разбиения на предложения заметно падает

Кодировка HTML определяется сама: объявленный charset, затем utf-8, cp1251, koi8-r, с отбраковкой заведомо неверного результата.

9. Публикация на GitHub Pages

Ссылка в заметке ведёт на фрагмент только тогда, когда читалка доступна по общему адресу. Базовый адрес нигде не прописан — читалка берёт его из location.href, так что настраивать ничего не нужно: где выложили, оттуда и работает.

Разложить репозиторий

index.html                 список книг, собирается rebuild
reader.html                руководство для участников
docs.html                  эта документация
.nojekyll                  пустой файл
books/
  manifest.html            читалки
  manifest_img/            картинки из книги
  state.html
  …                        реестры, .lock.json, .txt, исходники .fb2
bookreg.py  docs2html.py  READER.md  DOCS.md  CLAUDE.md
t_reader.js  seq.js … seq5.js       стенды, на сайт не нужны

.nojekyll нужен, чтобы GitHub Pages отдавал файлы как есть, без обработки Jekyll. Без него всё, что начинается с подчёркивания, молча выпадает.

Включить

Settings → Pages → Source: Deploy from a branch, ветка main, папка / (root). Через минуту сайт доступен:

https://ПОЛЬЗОВАТЕЛЬ.github.io/РЕПОЗИТОРИЙ/
https://ПОЛЬЗОВАТЕЛЬ.github.io/РЕПОЗИТОРИЙ/books/state.html#2.3.9.2

Дальше обычный git push = обновлённый сайт.

Что стоит знать

  • На бесплатном тарифе Pages работают только из публичного репозитория, и сайт публичный. Приватная публикация — только на GitHub Enterprise Cloud; на Pro закрыть можно репозиторий, но не сайт.
  • Отсюда практическое: тексты, которые нельзя выкладывать открыто, на GitHub Pages класть не стоит. Маркс, Энгельс и Ленин — общественное достояние, с ними вопросов нет; для более поздних книг понадобится закрытый хостинг.
  • Кириллица в именах файлов работает, но адрес получается процентно-кодированный. Читалки называются латиницей (state.html), так что это касается только исходников .fb2, на которые никто не ссылается.
  • Регистр в именах на Pages значимый, в отличие от macOS и Windows: локально ссылка может работать, а на сайте — нет.

Обновление

python3 bookreg.py rebuild books              # книги + index.html
python3 docs2html.py READER.md DOCS.md -o .   # reader.html и docs.html
git add -A && git commit -m "…" && git push

10. Известные ограничения

  • Поиск не пересекает границу предложения и абзаца.
  • Разные слова с одним смыслом («играла» / «сыграла») не отождествляются.
  • Приближение морфологии в браузере работает по первым пяти буквам: короткие слова с разными корнями изредка совпадут.
  • Подзаголовки внутри главы (<subtitle> в FB2, вроде «а) Феодальный социализм») своего уровня нумерации не получают. В оглавление они попадают, ссылка на них работает, но их абзацы нумеруются в пределах главы сквозняком. Если книге нужна нумерация и на этом уровне — подзаголовок должен быть <section> в исходнике: вложенность глав скрипт поддерживает любой глубины, якорь просто станет длиннее (3.2.1.14.5).
  • Стихи: каждая строка <v> — отдельный абзац со своим номером, то есть сослаться можно на строку. Выводятся без выключки по ширине, с отступом и курсивом. Строфы своей разметки не имеют.
  • Оформление внутри слова (курсивом выделена часть слова) сохранится, но при копировании цитаты в документ пропадёт: в буфер идёт чистый текст.
  • Таблицы переносятся, но своего номера не получают — как и картинки. Сложные таблицы с объединёнными ячейками схлопнутся в простую сетку.
  • Реестры, собранные с --no-lemma и без него, лучше не смешивать в одном проекте: команда search у первых работает хуже.
  • Накопитель, метки и состояние переключателя лежат в localStorage: они привязаны к браузеру, а не к человеку. С другого устройства их не видно, чистка данных сайта их стирает. Для накопителя это безразлично — он живёт минуты; для списка меток за год может стать заметно.
  • Правка READER.md и DOCS.md не доходит до сайта сама: нужен docs2html.py.
  • Читалка целиком грузится в браузер одним файлом. «Государство и революция» — 916 КБ, но по сети идёт 211 КБ: сервер отдаёт сжатым, а текст сжимается вчетверо. Половина объёма — поисковый индекс (208 КБ против 207 КБ самого текста), он нужен для поиска без сервера.

Порог примерно на порядок дальше: книга страниц на тысячу даст около 2 МБ в сжатом виде, и вот тогда понадобится либо резать читалку по главам (ссылки станут вида kapital-3.html#3.14.2), либо подгружать индекс отдельным файлом. До этого доводить не стоит.
